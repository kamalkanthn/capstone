# Dataset inspection for the 49-label isolated-sign model

**Assessment date:** 2026-11-09
**Scope:** choose a dataset for the existing 49-class isolated ISL recognizer. This report does not modify application or training code and does not download new datasets.

## Recommendation

Use the already downloaded **Amrita SLR archive as the primary dataset for the current 49-label model**. The extracted archive has exactly 49 labeled class folders and 978 isolated-sign videos, and those labels match the current model's 49-output class list. The public record describes 50 signs, so the one-class discrepancy must remain documented; do not invent or synthesize the missing class.

This is a compatibility recommendation, not a claim that Amrita alone is large enough for a high-accuracy, signer-independent system. It has only 18–21 clips per class in this local archive, and signer IDs are absent. Its currently reported test baseline is 54.4% accuracy and 0.524 macro-F1 on a random clip split; the split is not signer-disjoint. More data and a signer-aware test are needed before claiming generalization.

**Do not concatenate INCLUDE labels into Amrita's 49 classes yet.** The AI4Bharat label maps have 27 surface-form overlaps with the Amrita labels (13 in INCLUDE-50), but that is only a lexical-name comparison. Sign identity, regional variant, annotation scope, and signer split must be confirmed for every mapped class by inspecting examples and consulting an ISL reviewer. Similar English names must stay separate until that review approves the mapping.

INCLUDE is the best candidate in this list for a later isolated-sign expansion or comparison: it is explicitly an isolated ISL dataset, has official train/validation/test path lists and many more classes. It does not match the existing 49 labels exactly, and its current archive is about 56.75 GB compressed. It should be considered only after a reviewed mapping and a signer/video leakage audit. iSign, ISL-CSLTR, and ISLVT are sentence/translation resources, not drop-in 49-class isolated-sign video sets.

## Vocabulary cross-check

The existing model's class list is sourced from the local checkpoint and agrees with the 49 Amrita folder-derived labels. Comparing these strings with the AI4Bharat INCLUDE label maps after case and spacing normalization yields 27 names in full INCLUDE:

`afternoon, bad, bird, black, boy, brother, cat, cow, dog, evening, father, fish, friend, girl, good, good morning, grey, hello, mother, night, ring, student, teacher, thank you, today, tomorrow, yesterday`.

The 13 names present in INCLUDE-50 are:

`bird, black, boy, brother, cow, dog, father, girl, good, good morning, hello, teacher, thank you`.

These are **candidate lexical correspondences only**, not an approved label map. The datasets may encode different sign variants or annotation decisions even when their English labels match. Similar-looking pairs such as `monsoon` / `exmonsoon`, `you are perfect` / `youplural`, and `drinking` / `drink` are not to be merged. `good` and `good morning` are also distinct classes. Keep all source labels and source IDs in any future crosswalk; require ISL-literate review before collapsing classes.

iSign's sentence text and ISL-CSLTR/ISLVT's sentence/gloss annotations do not establish isolated instances for these 49 labels. No class coverage is inferred from a word merely appearing inside a sentence.

## Current pipeline and evaluation context

The existing dataset pipeline uses 12 ordered frames per clip at 160×160. The current checkpoint is a compact **MobileNetV3-Small + bidirectional GRU**, rather than MobileNetV2 + LSTM. It outputs ranked labels from the Amrita-derived 49-class list. The clean clip-level test baseline is 54.4% accuracy, macro-F1 0.524, and mean decode-plus-model latency 194 ms/clip; see [baseline experiment](BASELINE_EXPERIMENT.md). Per-class recall is in the saved experiment report. Because source signer IDs are missing, these results do not measure signer-independent generalization.

The project already has an exact dataset-label-to-recorded-clip lookup in the local API. It is a separate lookup from recognition and can serve supported Amrita labels; it is not sentence-to-ISL translation or avatar animation.

## Decision gates before dataset mixing or application changes

1. Keep Amrita as the primary dataset for the current 49-label model; preserve the existing label list and current split for reproducibility.
2. Before using INCLUDE as supplemental training data, download only the reviewed subset after measuring the category-part sizes, verify each candidate mapping with video and ISL review, and check duplicates/source videos across official splits. Do not assume signer disjointness.
3. For an honest signer-independent benchmark, acquire verified signer IDs or use a dataset with signer labels and design a grouped split. Amrita's current archive cannot support that claim.
4. Keep iSign, ISL-CSLTR, and ISLVT in the continuous sentence/translation track unless a separate isolated-word annotation is verified. Do not fold sentence clips or still images into the 49-class model.
5. Only after the dataset and mapping review, implement or change frame extraction, MobileNetV2/LSTM selection, ranked output, lookup, and evaluation. Retain 12-frame/160×160 preprocessing and evaluate accuracy, macro-F1, per-class recall, and inference latency on a frozen signer/video-safe test set.
